Keep this branch unmerged and undeployed during the 2026 season. No production
migration, feature flag, normal navigation, league conversion, scoring worker,
or trade-worker integration is part of this preview.

## Local setup

Use a disposable PostgreSQL database named `dynasty` bound to localhost. Apply
Alembic head to that database, then set `DYNASTY_DISPOSABLE_DATABASE_URL` to its
SQLAlchemy URL and run `PYTHONPATH=. python scripts/seed_dynasty_preview.py`.
The seeder refuses remote databases and production and inserts fictional QA
data only. Never use it against a development database containing real records.

Start the API with `DATABASE_URL` pointing to the same disposable database,
`ENVIRONMENT=development`, `BETA_ACCESS_ENABLED=false`, and
`DYNASTY_PREVIEW_ENABLED=true`. Set matching `GIT_SHA`, `WEB_GIT_SHA`, and
`WORKER_GIT_SHA` to the checked-out commit so the existing runtime gate passes.
Run `uvicorn collegefootballfantasy_api.app.main:app --host 127.0.0.1 --port 8547`.

Start Vite with `VITE_DYNASTY_PREVIEW_ENABLED=true`,
`VITE_BETA_ACCESS_ENABLED=false`, and
`VITE_API_PROXY_TARGET=http://127.0.0.1:8547`. Use an unused localhost port and
visit `/labs/dynasty`. These flags default off. Server denies production while
`CURRENT_SEASON_YEAR < 2027` even if mistakenly enabled. Preview routes are also
omitted from the public OpenAPI document.

Synthetic QA accounts: `dynasty-qa-0@example.invalid` (commissioner/admin) and
`dynasty-qa-1@example.invalid`; local-only password `DynastyPreview2027!`.
All names and eligibility evidence generated by the seeder are fictional.

## Workflow and verification

1. Create a two-team 2027 league, eight roster slots, two startup rounds, one
   freshman round, two future pick years. Join as the second QA account.
2. Start once. Refresh and retry start; order must stay fixed. Complete four
   selections as each pick's current owner; round two reverses round one.
3. Propose a future-pick exchange. Only the recipient can accept. Accept twice;
   ownership changes once and original franchise identity remains unchanged.
4. Enter both final records and playoff finishes after reviewing the season.
   Close, then open 2028. Existing players remain; no missing fact implies an
   exit. Only explicit reviewed `eligible=false` facts remove players.
5. Verify the pool contains only reviewed 2028 first-entry freshmen. Make roster
   space if needed and complete the freshman draft. Inspect the 2027 archive.
6. Disable the frontend flag: `/labs/dynasty` must resolve to the existing 404
   page. Disable server flag: capability and all dynasty endpoints return 404.
   Normal league creation must contain no dynasty option.

API requests are in `bruno/collections/backend-api/DynastyPreview`. Use existing
Login to obtain each account's token; set `base_url` to the local API. Catalog
requires admin. Use IDs from responses; no automatic production credentials or
cross-account consent. The main 2026 happy-path collection stays unchanged.

Run `pytest tests/api/test_dynasty_preview.py` using SQLite, then run it with
`CFF_TEST_DATABASE_URL` set to disposable PostgreSQL to exercise simultaneous
selection and acceptance. That test fixture drops/recreates registered tables;
it must never point to a database you need to keep. Run frontend Vitest and
`npm --prefix web run typecheck`. Migration checks require upgrade, Alembic check,
downgrade to `0125_challenge_experiences`, and upgrade again on disposable data.

## Preview rules and remaining launch work

Dynasty tables own all leagues, franchises, rosters, trades, picks and season
snapshots. Existing account and player identities are referenced read-only.
Normal league IDs and dynasty league IDs are separate namespaces.

All league mutations serialize using a PostgreSQL row lock. SQLite tests check
behavior only. Used picks and same-season selected players cannot be reused,
even if the player is dropped. Season closure freezes history and blocks roster
changes until rollover. Pending offers revalidate every asset at acceptance.
Future-pick ownership survives numbering and rollover. Missing catalog facts
retain roster ownership but cannot authorize new selections.

Preview value v1 uses reviewed base value × class factor × age factor. Class
factors: FR 1.20, RSFR 1.15, SO 1.10, RSSO 1.08, JR 1.00, RSJR .98,
SR .90, RSSR .85, GR .80, unknown 1.00. Age as of August 1 contributes
`clamp(.80, 1.10, 1 + (21 - age) * .02)`; unknown age is neutral. No base value
means **unrated**, never zero. These are explicit provisional weights pending
product review and never overwrite current player ratings.

Before 2027 launch: review real player/freshman coverage and a season-safe import
path for new identities, finalize roster rules/value weights, integrate normal
lineups, scoring, waivers and authoritative postseason results, resolve tied
playoff finishes, add automatic season scheduling as needed, and approve the
separate release. This preview is not a complete playable scoring season yet.
